# Mac: build, run, verify

Source of truth: `scripts/mac-run.sh`, `scripts/mac-dev-cert.sh` (`--help`), `docs/development.md`. If they differ from this skill, fix the skill. Toolchain/Xcode problems → skill `toolchain`.

## One-time: dev signing identity (user runs it)
```bash
scripts/mac-dev-cert.sh            # creates self-signed "PenBridge Dev" in the login keychain
scripts/mac-dev-cert.sh --check    # present + trusted?
scripts/mac-dev-cert.sh --delete   # then mac-run.sh --reset-tcc once
```
- It asks for the **login password** (trust setting) and the first codesign may ask "codesign wants to use key" → Always Allow. Agents can't answer those prompts — ask the user to run it.
- Why: TCC stores the grant against the designated requirement. Ad-hoc = cdhash → changes every build → grant silently lost (toggle still looks on). Signed with the cert, the requirement is `identifier "com.blake11.penbridge" and certificate leaf = H"…"` → survives rebuilds.
- codesign works even while the cert is **untrusted** (`find-identity` shows `CSSMERR_TP_NOT_TRUSTED`); the leaf hash pins it, so trust is cosmetic.

## Run
```bash
scripts/mac-run.sh                 # Debug build → sign → open (kills a running instance first)
scripts/mac-run.sh --release       # dotnet publish -c Release → universal NativeAOT app (#42)
scripts/mac-run.sh --no-build      # relaunch last build
scripts/mac-run.sh --reset-tcc     # tccutil reset Accessibility com.blake11.penbridge, then run
scripts/mac-run.sh --reset-keychain   # delete all com.blake11.penbridge Keychain items (Release; asks "yes"; pairings lost)
scripts/mac-run.sh --reset-dev-secrets   # delete ~/Library/Application Support/PenBridge-Dev/secrets (Debug store; asks)
scripts/mac-run.sh --logs          # + log stream --style compact --level debug --predicate 'process == "PenBridge"'
scripts/mac-run.sh -- <dotnet build args>   # e.g. -- -p:ValidateXcodeVersion=false
scripts/device-preflight.sh        # before any injection/device step: screen unlocked, Accessibility, server listening, adb, gh scopes; non-zero + hint
scripts/device-test-setup.sh       # device-test round: preflight, Release app, Android install, reconnect, latency + filtered captures; prints PIDs + stop command
```
- **Sandbox:** the Claude Code Bash sandbox blocks keychain private-key access, so signing fails there (`errSecInternalComponent`). `.claude/settings.json` `sandbox.excludedCommands` runs `scripts/mac-run.sh`, `scripts/mac-sign.sh`, `scripts/device-test-setup.sh`, `scripts/check-bundle.sh --mac` and `dotnet build|publish src/PenBridge.Mac…` outside it (their child `codesign` calls inherit that). Sign through those scripts rather than calling `codesign` directly. Matching is on the call text: run them alone, not chained with `&&`, `cd`-prefixed or redirected to a file, or they stay sandboxed. A failed signing build can leave a broken seal: `rm -rf src/PenBridge.Mac/bin src/PenBridge.Mac/obj` and rebuild.
- **Every build signs** (`dotnet build`/`run`, Rider, mac-run.sh; #55): target `PenBridgeSelectDevSigningIdentity` in `PenBridge.Mac.csproj` (BeforeTargets `_DetectSigningIdentity`) runs `security find-identity -p codesigning` (no `-v`: untrusted self-signed is fine; ~20 ms) and, if "PenBridge Dev" is listed, sets `CodesignKey` **and the SDK-private `_SpecifiedCodesignKey`** (the SDK copies CodesignKey into it at evaluation, so setting only CodesignKey in a target does nothing). `PenBridgeCheckDevSigningIdentity` errors if the SDK then resolves `-`. No identity → ad-hoc + a build message. Opt-outs: `-p:PenBridgeDevSigning=false`, `-p:PenBridgeDevCodesignKey=<name>`, explicit `-p:CodesignKey=`. Exec chosen over a marker file: never stale after `mac-dev-cert.sh --delete`/Keychain Access edits.
- The SDK's own signing (`EnableCodeSigning`, default true) **does** sign every `Contents/MonoBundle` dylib correctly (13 in a JIT bundle, only the 5 `libSystem.*.Native` under NativeAOT; all verify `--strict`) and applies `Entitlements.plist` to JIT builds; Debug and universal Release launch fine. mac-run.sh's "already signed?" probe checks any MonoBundle dylib (there is no `libcoreclr.dylib` under NativeAOT). Only `EnableCodeSigning=false` + re-signing the bundle alone crashes (below).
- `build-release.yml` publishes with `-p:EnableCodeSigning=false` (target skipped) and signs with `scripts/mac-sign.sh --no-entitlements <app> <identity>`: each MonoBundle Mach-O, then `codesign --force --deep --identifier com.blake11.penbridge`, `Entitlements.plist` if present; `--hardened` = `--options runtime --timestamp`. mac-run.sh only falls back to mac-sign.sh when the bundle lacks `Authority=PenBridge Dev` (old build, `--no-build`, `-- -p:EnableCodeSigning=false`).
- Check the signature: `codesign -dr - <app>` must show a certificate hash (`certificate root = H"…"` for our self-signed cert — root == leaf), not `cdhash`. `codesign -dvv` (two v) shows `Authority=PenBridge Dev`.
- **MonoBundle dylibs**: the build rewrites the Microsoft-signed runtime dylibs in `Contents/MonoBundle` (signature becomes invalid) and with `EnableCodeSigning=false` nothing re-signs them; `codesign --deep` treats MonoBundle as resources, so `codesign --verify --deep` still passes. Result: instant `SIGKILL (Code Signature Invalid)`, "Invalid Page" in dyld, crash report in `~/Library/Logs/DiagnosticReports/PenBridge-*.ips`. `mac-sign.sh` signs (and verifies) each MonoBundle library before the bundle; check one with `codesign -v <app>/Contents/MonoBundle/libcoreclr.dylib`.
- **Hardened runtime** (`mac-sign.sh --hardened`): CoreCLR needs `com.apple.security.cs.allow-jit` (else "Failed to initialize the VM", exit 134). Testing it with the self-signed dev cert also needs `com.apple.security.cs.disable-library-validation` (no Team ID → dyld "different Team IDs"); a Developer ID cert doesn't. NativeAOT doesn't JIT: the Release app is signed without entitlements, verified launching hardened with only `disable-library-validation`. Two SDK defaults had to be undone for the AOT publish (csproj, condition `PublishAot` and `_IsPublishing`, because `_UseNativeAot` is defined after the project body): `EnableDefaultCodesignEntitlements=false` (else it picks up `Entitlements.plist` by itself), and `<CustomEntitlements Include="com.apple.security.cs.allow-jit" Type="Remove" />` (`_CompileEntitlements` adds allow-jit to **every** desktop Release signature otherwise). Check: `codesign -d --entitlements - <app>` shows an empty dict. build-release and mac-run's fallback re-sign pass `mac-sign.sh --no-entitlements` for NativeAOT bundles.
- **Shell pitfall (`set -o pipefail`)**: `cmd | grep -q pattern` fails with 141 (SIGPIPE) when grep exits on the first match while `cmd` is still writing. `codesign -dvv <aot app> | grep -qxF Authority=…` failed every time, so mac-run.sh re-signed every AOT build. Capture first: `out="$(cmd)"; grep -q … <<<"$out"`.
- Process name `PenBridge` comes from `<AssemblyName>PenBridge</AssemblyName>` (default would be `PenBridge.Mac`); bundle id `com.blake11.penbridge`.
- Output: Debug → `bin/Debug/net10.0-macos/osx-arm64/PenBridge.app` (JIT). **Release = `dotnet publish -c Release`** (`PublishAot`; the SDK honours it only when publishing, `_UseNativeAot` = PublishAot and `_IsPublishing`): osx-arm64 + osx-x64 intermediates and the universal NativeAOT `bin/Release/net10.0-macos/PenBridge.app` (~15 MB vs ~240 MB JIT; stripped, symbols in the sibling `PenBridge.app.dSYM`), which mac-run.sh picks. `dotnet build -c Release` still gives an untrimmed JIT bundle. Publish without `-p:CreatePackage=false` also writes a ~90 MB `.pkg` to `publish/`.
- NativeAOT defaults to full trimming of every assembly; don't set `LinkMode`/`TrimMode` (the SDK warns under NativeAOT). Trim/AOT warnings come from ILC at publish (0 today); `IsAotCompatible` turns the analyzers on in Debug too. Incremental publishes keep stale files: `rm -rf src/PenBridge.Mac/bin src/PenBridge.Mac/obj` after switching JIT↔AOT (an old JIT `libcoreclr` etc. lingered in the first AOT bundle).
- No GNU `timeout` on macOS: run the binary with `&`, `sleep`, then `kill`; exit 137 = killed by the system (signing), 143 = your SIGTERM.

## LSUIElement / menu bar
- `LSUIElement=true` + `ActivationPolicy.Accessory`: no Dock icon, no app menu, no Cmd-Tab; only the `NSStatusItem`. Nothing visible → check `--logs` for a crash, or run the binary in `<app>/Contents/MacOS/` from a terminal for stdout.
- Windows (pairing PIN/QR) must activate the app to come to front.
- On notched displays a crowded menu bar can hide the icon.
- Verify headless: `lsappinfo info "$(lsappinfo find bundleid=com.blake11.penbridge)"` shows `type="UIElement"` (no Dock icon). Agents can't confirm the status item: `screencapture` needs Screen Recording ("could not create image from display") and `osascript`/System Events needs Accessibility for the terminal — ask the user to look.
- Idle: 0.0% CPU. Memory: section "Memory and startup" below.

## Self-screenshot (Mac UI turn)
`screencapture` works from an agent's Bash here (the terminal host already has Screen Recording). If it ever returns only wallpaper/menu bar, granting Screen Recording to the host app is a one-time user step: say so, don't pretend.
- Run the Debug build (`scripts/mac-run.sh`), open the window under test, then capture just it: `screencapture -x -o -l <windowId> $SCRATCH/w.png`. Get the id with a swift script over `CGWindowListCopyWindowInfo([.optionOnScreenOnly], kCGNullWindowID)` filtered on `kCGWindowOwnerName == "PenBridge"` (`kCGWindowNumber`; ~2 s; python has no Quartz). Only this window form (`screencapture -x -o -l …`) is auto-allowed; anything else prompts the user.
- Never capture the full screen: it holds the user's other windows. Write PNGs under the scratchpad, Read them, fix clipped or overlapping layout, quit the app after.

## App icon
- Put an Icon Composer `.icon` folder in `src/PenBridge.Mac/Resources/` and set `<AppIcon>AppIcon</AppIcon>` in the csproj. The SDK picks up `**/*.icon` and `**/*.xcassets`; actool emits `Assets.car` (macOS 26+) and `AppIcon.icns` (macOS 14/15) plus both Info.plist keys. actool's `AppIcon.icns` stops at 256 px, so the csproj target `PenBridgeUseFullSizeLegacyIcon` swaps in the committed `Resources/AppIconLegacy.icns` (16..1024 px, rendered from `Assets.car` by `scripts/lib/car-to-iconset.swift` via `gen-icons.sh`; `--check` asserts a 1024 px representation). Commit it after any icon change (#109).
- Universal publish = an outer build plus per-RID inner builds. Workload-internal items (actool output in `_BundleResourceWithLogicalName`) exist only in the outer build, so custom targets must tolerate empty lists in inner builds and fail only when actool produced resources but no `AppIcon.icns`. `qlmanage` on a `.icon` hangs; `touch` on a nonexistent path creates a file.
- Menu-bar template SVGs must not use `<mask>` (CoreSVG renders masks blurry at native size); use clip paths.
- Regenerate icons with `scripts/gen-icons.sh [--check|--preview]`.

## Accessibility (TCC)
- `AXIsProcessTrusted()` false → posted CGEvents are dropped silently. The app prompts and links to System Settings ▸ Privacy & Security ▸ Accessibility.
- Granted but nothing happens: signature changed → `--reset-tcc`, trigger injection, grant again. If it ever ran unsigned, remove the old entry with `–` first.
- The grant is per signed identity; running a build from another worktree path may need a re-grant — prefer running from the main tree.

## Verifying tablet input
- No phone: `tools/PenBridge.SimClient` streams scripted strokes to the server.
- **Krita** is the reference: pressure brush; Settings ▸ Configure Krita ▸ Tablet settings has a pressure tester. Expect width varying with pressure; tilt affects tilt-aware brushes.
- Proximity-enter (`kCGEventTabletProximity`, pen/eraser) before tablet-point mouse events, proximity-leave after — without it many apps treat input as a plain mouse.
- Pressure 0..1 in `kCGTabletEventPointPressure` (subtype `TabletPoint`) and `kCGMouseEventPressure`; tilt −1..1.
- While down use `LeftMouseDragged`, not `MouseMoved`; unmatched down/up leaves apps stuck (150 ms pen-up watchdog covers packet loss).
- Sanity-check in Preview/Notes (mouse behaviour) and on multiple displays/regions.
- **CGEvent timestamps = nanoseconds on CLOCK_UPTIME_RAW**, not mach ticks (measured on Apple silicon, timebase 125/3): an NSEvent made with timestamp t s converts to a CGEvent timestamp of exactly t·10⁹ = `clock_gettime_nsec_np(CLOCK_UPTIME_RAW)`, and NSEvent reads a CGEvent's timestamp as ns. `CGEventCreate*` leaves it 0 (the window server stamps on post). On macOS `Stopwatch.GetTimestamp()` is that clock at 1 GHz; convert with `TabletEventMath.TicksToNanoseconds(ticks, Stopwatch.Frequency)`.
- Hot path posts through raw handles (`CGEventCreateMouseEvent`/`CGEventSet*ValueField`/`CGEventSetTimestamp`/`CGEventPost`/`CFRelease`), not the `CGEvent` binding, which allocates a managed wrapper per event. The bound `CGEventField`/`CGEventType` enums give the field ids.
- **Latency (P3-D):** `scripts/latency-report.sh --enable`, then restart the app (`open` drops env vars, so `PENBRIDGE_LATENCY_LOG=1` only works when launching the binary directly or with `open --env`). Device-test rounds: `scripts/device-test-setup.sh` enables it and starts filtered captures (`log stream --predicate 'subsystem == "com.blake11.penbridge"'`, logcat by pid) under `.claude/progress/<feature>/<round>/`. Draw, end the session (or `--dump-now`, which sends SIGUSR1), then `scripts/latency-report.sh`. Dumps are in `~/Library/Logs/PenBridge`; SimClient `draw --in-process-server --repeat 6` with the env var checks the pipeline without a phone (`--sim`). The capture setting persists as a user default: turn it off after measuring with `scripts/latency-report.sh --disable`.
- **Agent smokes need an unlocked, awake screen.** `scripts/device-preflight.sh` checks it (and the rest); by hand: `ioreg -n Root -d1 -a | grep -A1 CGSSessionScreenIsLocked` (true = locked) and `system_profiler SPDisplaysDataType | grep Asleep`. While the display sleeps the app logs "No active display" and drops all input, and a new Release build's Keychain prompt waits unseen behind the lock screen (no "Server listening"). Don't inject into the lock screen; report the smoke as a user step.
- Headless injection check (no Screen Recording needed): another process polling `CGEventGetLocation(CGEventCreate(NULL))` sees the cursor follow a SimClient `draw circle`.
- **Sandboxed compile check (reviewers/agents):** the Mac head builds inside the sandbox unsigned with `-p:EnableCodeSigning=false -o <scratch dir>`; running and signing still need the unsandboxed forms.
- **Agent-driven UI checks:** Esc via `osascript -e 'tell application "System Events" to key code 53'` (events posted from a fresh unsigned binary don't arrive). Force light mode for the app only: `defaults write <bundle-id> NSRequiresAquaSystemAppearance -bool YES` + relaunch (`open --args -AppleInterfaceStyle` does nothing; delete the key afterwards). Bring the target app frontmost (AX `kAXFrontmost`) before each scripted stroke, else it goes to the frontmost app (probe field 40 = target pid). An AX `click` on a status-menu item doesn't activate an accessory app, so its windows aren't key. Another agent's region overlay can cover the screen in screenshots: check frames. `HOME=<dir> dotnet run file.cs` triggers first-run in that HOME: pass paths via env vars.
- Headless pairing of SimClient with the Debug app: AX-press status item "Pair new device…", read the 6-digit AXStaticText, pipe into `penbridge-sim pair --pin` with a private HOME.
- Region overlay: an even-odd hole for a full-display region removes all dimming; outline the current region and cut a hole only for the live drag.
- Recover private AppKit behaviour with an in-process swizzling harness plus lldb disassembly (resolve `objc_msgSend$sel` stubs: adrp/add x1 = selector string).
- Binding member names: read the ref assembly with a System.Reflection.Metadata script (XML docs are incomplete). Names drop the `Color` suffix (`NSColor.Label`); `cancelOperation:` needs `[Export]`.

## Gesture events (mac-gesture-events; ADR-0023, measured on macOS 27)
Code: `src/PenBridge.Mac/Input/CGEventGestureInjector.cs` (two-finger) and `CGEventSystemGestureInjector.cs` (three/four-finger).

| What | How |
|---|---|
| Gesture event | `CGEventCreate(src)` + `CGEventSetType(29)` (undocumented kCGSEventGesture) |
| Field 110 = HID type | 8 zoom (NSEventTypeMagnify), 5 rotate, 22 smart zoom (no phase), 6 scroll (swipe companion); 61/62 begin/end wrappers not needed |
| Value fields | shared storage: 113/114/118 one slot, 119/139 the next — set only the one the type uses. 113 magnification (per-event delta, apps scale by 1+m), 114 rotation (degrees, + = counterclockwise), 118/119 companion scroll x/y |
| Phase | field 132 (gesture) / 99 (scroll): 1 Began, 2 Changed, 4 Ended, 8 Cancelled, 128 MayBegin (NSEvent 1/4/8/16/32). Magnify/rotate: Cancelled behaves like Ended (Safari keeps the zoom). Scroll: see the Cancelled pitfall below |
| Momentum | scroll field 123: 1 begin, 2 continue, 3 end; no companion (fingers are up) |
| Scroll | `CGEventCreateScrollWheelEvent2(src, pixel, 2, wheelY, wheelX, 0)`, integer points only → carry the remainder. Positive wheel = content moves down/right |
| Natural scrolling | posted events are not inverted by the system: natural on → wheel = +finger delta, off → negate. Pref `com.apple.swipescrolldirection` (kCFPreferencesAnyApplication, absent = on); cache it, refresh on the distributed notification `SwipeScrollDirectionDidChangeNotification` (no polling). Field 137 = isDirectionInvertedFromDevice (sign unchanged; set it like a real device) |

- **Swipe between pages** needs, before each phased scroll event, a type-29 companion (110 = 6, 132 = the same phase, 118/119 = the unrounded deltas). The Began delta must be nonzero, otherwise AppKit's `trackSwipeEvent` starts and stays at the first amount, then cancels. Safari goes back for +dx (content moves right).
- **A posted Cancelled scroll leaves AppKit's gesture open:** the view gets phase Cancelled, then on the next phased scroll event AppKit synthesizes an Ended carrying *that* event's deltas (the next scroll's first delta lands twice; a MayBegin gets one with zero deltas). Post an Ended (zero deltas, with its type-29 companion) right after the Cancelled: closed at once. Don't end with Ended alone: a page swipe in `trackSwipeEvent` commits on Ended (amount → 1) and aborts on Cancelled (→ 0), also when the Ended follows. Magnify/rotate Cancelled don't have this.
- **Frontmost only:** magnify, rotate and smart zoom reach only the active app (dropped over an inactive window; target pid, `CGEventPostToPid`, the 61/62 wrapper don't help). Scroll reaches the window under the cursor.
- **Preview follows whichever magnify/rotate stream began first** and ignores the other for the rest of the gesture, so open the *dominant* one first (Core `TransformStreams`, #214): hold both back until the larger of |magnification| and |rotation in radians| (each finger's radial vs tangential travel over half the spread, like for like) reaches 0.02, open that one, and let the other join only past 0.25 / 15° accumulated since the first opened (its earlier drift is dropped). Don't use separate per-stream thresholds: the recognizer's pinch Began already carries everything since landing (a twist locks at ~23° for a 200 pt spread), so a twist's few % of spread drift crossed the magnify threshold in the same event and magnify, posted first, won.
- Any posted mouse/scroll/gesture event **with a location** moves the cursor there; leave the location at the `CGEventCreate` default (current cursor) to keep it still. Posted click state is used as is (no automatic counting); mouse-up defaults to 0, so set it to the down's value.
- Track which phases were actually posted open: after an Accessibility revoke the ends were skipped, so close them when the grant returns.
- **Four-finger fallbacks** (Dock events type 30 / HID 23 did nothing on a Mac without a trackpad): ⌃↑ keycode 126 / ⌃↓ 125 (flags ctrl+fn) toggle Mission Control / App Exposé; F11 keycode 103 (fn) toggles show desktop; ⌃←/→ 123/124 switch Spaces; the launcher is `/System/Applications/Apps.app` (opening it again toggles it). Three-finger drag = LeftDown at the cursor, LeftDragged at previous + delta, LeftUp.
- **Posted keystrokes leave their modifiers in the HID state:** after a key event with ⌃+fn flags, `CGEventSourceFlagsState(HID)` stays ⌃+fn and every later event created from a HID-state source inherits them (a pen click becomes a ⌃-click). Post a FlagsChanged (type 12) with the previous flags after the key-up. Check with `CGEventSource.flagsState(.hidSystemState)`.
- **Event probe (`tools/cgevent-probe`, `scripts/cgevent-probe.sh build|record|post`):** start here for any injection bug. `record [--types 22,29] [--raw] [--all]` is a listen-only tap printing ns timestamps, `nsts=` (what AppKit sees), NSEvent phase/touches and every non-zero field; `post -e 'at X Y; move; gesture hid=22 loc'` posts a scripted sequence (mouse, phased scroll, type 29/30 with any `fN=` field, `raw <hex>` replays of `record --raw` lines, `repeat N … end`). Syntax and examples: its README. Compare a real trackpad recording with PenBridge's (`record` while the S23 does the gesture), then post variants into the target app.
  - **Real trackpad over LAN** (the dev Mac has none): `scripts/cgevent-probe.sh build`, serve `.build/cgevent-probe/` with `python3 -m http.server`, `curl -fO` `record` on the MacBook, `./record --raw > mbp.log` (Terminal needs Input Monitoring there), send it back with `nc -l <port> > mbp.log` / `nc <dev-mac>.local <port> < mbp.log`. The binaries target macOS 14+ and need nothing else.
  - **`post` must run unsandboxed** (an agent's sandboxed shell): sandboxed posts still show up in a session tap but apps never get them, with no error. Posting into the user's apps is a user-visible action: an agent needs the user's go-ahead for that and for reading the result through AX.
  - The window server overwrites the source fields of a posted event (f39-f44 connection/pid/uid, f58 and f169 timestamps, f59, f85, f102, f107), so those can't be set and can't explain a posted-vs-real difference. Real devices put mach ticks in f169 and ns in f58; posts get ns in both; `NSEvent.timestamp` follows f58 (correct either way).
  - A real trackpad brackets every two-finger tap with a stream of type 29 events with no f110 (NSEventTypeGesture, `touches=` with NSTouch phases), about 8 ms apart while fingers are down; smart zoom (f110 = 22) is posted with the last one's timestamp. PenBridge posts the smart zoom alone. `record --raw` on a MacBook captures that stream for `raw` replay.
- **Headless verification:** a listen-only CGEventTap (fields), an NSView logging NSEvents (must be the active app for gestures), a local page reporting scroll/visualViewport/gesture*/contextmenu to a local HTTP server, AX sizes (Preview AXImage). Mission Control / App Exposé open = the Dock process's AX children gain an `AXGroup` with AXIdentifier `mc` / `appexpose` (needs Accessibility for the probe's host). Pair SimClient via the menu's "Pair new device…" and read the PIN through AX (PenBridge's AXExtrasMenuBar, then its window); a private `HOME` gives SimClient its own pairing store. Make a probe window frontmost with `AXUIElementSetAttributeValue(app, kAXFrontmostAttribute, true)` (the user's app may be in front); press menu items/buttons via AX instead of posting ⌘-keystrokes (posted modifiers stick in the HID state). Safari back/forward needs history made by a user gesture (WebKit skips entries from JS redirects/`location.hash`): navigate with a posted click on a link. A SimClient pen script lands at its mapped display point, maybe in the user's window: put a probe window there first.

## Menu-bar shell notes (`src/PenBridge.Mac/Shell`)
- **Carbon P/Invoke types:** `ItemCount` and `ByteCount` are `unsigned long` → `nuint`; `UInt32`/`OSType`/`OptionBits` → `uint`; `OSStatus` → `int`. A `uint` passed for an `ItemCount` leaves the upper 32 bits of the 64-bit argument register undefined, so the callee may read a huge count.
- **Global hotkey:** `RegisterEventHotKey` without `kEventHotKeyExclusive` can silently share a combination with another app (both fire). Register exclusively so a conflict fails with an error, and show the menu item as unavailable.
- **Modal UI and the main queue:** distributed notifications and `DispatchQueue.MainQueue` blocks run inside the serial main-queue drain. An `NSAlert.RunModal` or menu tracking loop started from one stalls every other main-queue block (ServerHost events, `DispatchAfter`) until it closes. Start modals from menu actions or a run-loop perform (`BeginInvokeOnMainThread`), never from a GCD block or an `await` continuation that may run in one.
- **Accessibility UX:** the system `AXIsProcessTrustedWithOptions(prompt)` dialog shows once, at first launch without the grant; "Grant Accessibility…" only opens the Settings pane, so the two never overlap.
- **Agent testing without clicks:** `NSControl.PerformClick(null)` throws in the binding; a status button's `PerformClick` didn't open its menu on this macOS, but `menu.PopUpMenu(null, point, button)` did. Debug-level os_log lines exist only in memory: use `log stream --level debug`, not `log show`. `HOME=/tmp/x penbridge-sim …` keeps SimClient pairings separate from other agents'.

## Mac services notes (`src/PenBridge.Mac/Services`)
- **Bonjour** uses the DNS-SD C API (`DNSServiceRegister` + `DNSServiceSetDispatchQueue` on the main queue, static `[UnmanagedCallersOnly]` reply callback; NativeAOT-clean). `NSNetService`/`NSHost` are obsoleted (CA1422 = build error). Check with `dns-sd -B _penbridge._tcp` and `dns-sd -L "<name>" _penbridge._tcp local`.
- **Instance name ≤ 63 UTF-8 bytes** (one DNS label), cut on a code-point boundary (`Utf8Text.Truncate`); the TXT `name` may be up to 250 bytes. Non-ASCII computer names ("Paul’s MacBook Pro", CJK, emoji) hit the label limit fast.
- Reply errors (mDNSResponder restart) → deallocate + re-register with 1→30 s backoff (one-shot `DispatchAfter`, no polling). Computer-name changes come from an `SCDynamicStore` notification on the computer-name key.
- **Secret store per config** (`Services/SecretStoreFactory.cs`, `#if DEBUG`): Debug → Core `FileSecretStore` in `~/Library/Application Support/PenBridge-Dev/secrets` (0700/0600, no Keychain, no prompts; startup log "Debug build: using development file secret store (not Keychain)"); Release → always `KeychainSecretStore`. Separate identities and pairings: a phone paired with Debug must pair again with Release. Check: same `fingerprint` in "Server listening…" across two recompiles; Release dll has no `FileSecretStore` TypeRef (`grep -c -a FileSecretStore …/MonoBundle/PenBridge.dll` = 0). Debug still logs `SecKeychainCreate/Delete` at startup: that is .NET's PKCS#12 import using a temporary keychain, no prompt. Don't launch a local Release build just to test: it reads the real Keychain items, and any recompiled Release build (new cdhash, #55) opens a SecurityAgent login-password prompt ("PenBridge wants to access key … pb.server-identity.pfx") that an agent can't answer; until the user does, the menu shows "Starting…" and pairing does nothing. Spot it with `CGWindowListCopyWindowInfo` (owner SecurityAgent, layer 1000) and read it through AX. Agents checking on screen without the user run the Debug build (file store, its own pairings); `device-test-setup.sh` always uses the Release Mac app, so it needs the user there after a rebuild.
- **Keychain prompts (#55, measured; Release builds)**: two layers. (1) ACL trusted-app list = creator's designated requirement (stable with PenBridge Dev, cdhash when ad-hoc). (2) **Partition list** `partition_id` = `cdhash:<main-exe cdhash>` for any code without an Apple Team ID, *including the self-signed dev cert*. A recompiled build (new cdhash, same DR) → read fails/prompts; "Always Allow" appends the cdhash. Incremental no-op builds keep the cdhash (no prompt). Explicit `SecAccessCreate` at add still gets the cdhash partition; `SecKeychainItemSetAccess` removing it → `errSecAuthFailed` (needs keychain password); `kSecUseDataProtectionKeychain` → -34018 (no entitlement); `codesign --team-identifier` with a self-signed cert → AMFI SIGKILL. `SecItemUpdate` from a new build succeeds silently and *resets* the partition to that build; `SecItemDelete` from a non-partition build → -25244. Untested way out: an Apple Development (free personal team) cert → `teamid:` partition.
- **Probing Keychain access headlessly**: a tiny C tool calling `SecKeychainSetUserInteractionAllowed(false)` turns "would prompt" into `-25293`/`-25308` instead of a dialog (a human at the screen may otherwise click it and skew results — a 5 s "success" was a click). `security dump-keychain -a` (no `-d`) shows ACL/partition; filter to one service with awk. `security delete-generic-password -s <svc>` deletes regardless of partition.
- **Keychain**: login (file-based) keychain; `kSecAttrAccessible` is ignored there. The first access by a newly signed/copied bundle can block for 10–50 s (securityd re-validates the signature, maybe a hidden "wants to use confidential information" prompt) → keep Keychain I/O off the main thread.
- **os_log**: `OSLogLevel.Info` entries aren't persisted by default; map Information → Default. Use `/usr/bin/log` in scripts (zsh has a `log` builtin).
- Parallel agents: `mac-run.sh` does `pkill -x PenBridge`; to test alongside another worktree's build, copy the .app, rename `Contents/MacOS/PenBridge` + `CFBundleExecutable`, and re-sign with `scripts/mac-sign.sh`.

## Memory and startup (NativeAOT, #42)
Measured 2026-10-13, MacBook (arm64), universal Release, menu-bar idle, server listening, same machine and session:

| Build | (a) idle at launch RSS / footprint | (b) connected-idle | (c) 5 min streaming (end) / after | launch → status item |
|---|---|---|---|---|
| JIT (untrimmed CoreCLR, before #42) | 205 MB / 164 MB | 209 / 127 MB | 105 / 90 MB; 112 / 90 MB | 771 ms |
| NativeAOT, default | 86 MB / 20 MB | 79 / 21 MB | 81 / 23 MB; 81 / 23 MB | 255 ms |
| NativeAOT + NSObject dlopen stub (shipped) | 50–62 MB / 19–20 MB | 60 / 22 MB | 61 / 25 MB; 61 / 25 MB | 168 ms |
| Floor: minimal Swift NSStatusItem app | 52 MB / 11 MB | | | |

- JIT numbers drift a lot with memory pressure (P2-C saw 74–77 MB RSS for the same build after longer idle): compare runs in one session, several launches each. Footprint is the stable metric (it counts compressed pages); `ps` RSS counts shared framework pages too, so it can never go below the AppKit floor (~52 MB).
- **The biggest win after AOT: `Foundation.NSObject`'s static constructor dlopens ~45 frameworks** (one private field per framework: WebKit, MapKit, GameKit, Photos, AVKit, …; pulls in SwiftUI, ~600 images in total, +28 MB RSS, under 1 MB footprint) so a dynamically registered app can find their classes. Under NativeAOT (static registrar, full trim) the SDK links every framework whose types survive (`otool -L`), so it's redundant. `src/PenBridge.Mac/Trimming.Substitutions.xml` stubs the public `ObjCRuntime.Dlfcn.dlopen(string, int)` (returns 0), passed to ILLink via `_ExtraTrimmerArgs --substitutions` only when `_UseNativeAot`. Its only callers in the trimmed `Microsoft.macOS.dll` are those fields; `Libraries.*.Handle` uses the internal `_dlopen`. In the *untrimmed* assembly there are other callers (`Runtime.RegisterAssembly`, `Dlfcn.SlowGet*` taking a library path): trimming removes them for us today, but a workload update or new API use could bring one back, and it would silently get a 0 handle.
- **Guard (automated, CI):** `scripts/check-bundle.sh --mac Release` runs `scripts/lib/check-aot-substitutions.cs` (System.Reflection.Metadata IL walk, no extra tools) on both RIDs' `obj/Release/net10.0-macos/<rid>/linked/Microsoft.macOS.dll`, the exact input to ILC. It fails ("workload update changed the dlopen callers; re-validate …") unless: the stub is applied (`ldc.i4.0; conv.i; ret`), every call is in `Foundation.NSObject::.cctor`, each is followed directly by `stsfld` into an NSObject field, and no `ldsfld`/`ldsflda` reads any of those fields (private, so only this assembly could). Verified it fails on the untrimmed runtime-pack assembly and on a changed expectation. Runtime sanity check: image count of the running app (`vmmap <pid> | awk '/^__TEXT/{print $NF}' | sort -u | wc -l`) ~730 (floor 719), not ~1230.
- check-bundle uses `<app>.dSYM` for symbols only when `dwarfdump --uuid` matches the executable for every architecture (a stale dSYM would vouch for code the binary may lack).
- How it was found: `lldb --batch` with `breakpoint set -n dlopen` + `p (char*)$x0` + `bt` (lldb disables ASLR, so `atos -o PenBridge.app.dSYM/Contents/Resources/DWARF/PenBridge -arch arm64 -l 0x100000000 <addrs>` symbolicates). `DYLD_PRINT_LIBRARIES=1 <app>/Contents/MacOS/PenBridge` lists load order. A C helper that `dlopen`s a framework list and sleeps measures a framework set's RSS cost.
- Linked-but-unused CloudKit/Intents (kept by `NSApplication.WeakDelegate`'s `typeof(_NSApplicationDelegate)` check, whose methods mention CKShareMetadata/INIntent) cost nothing extra: AppKit loads both lazily even in the Swift floor app.
- Tried via environment variables on the shipped binary, no measurable effect (3 runs each, within ±3 MB noise, footprint unchanged), not adopted. Caveat: that NativeAOT honoured the variables was not verified independently (the background GC thread starts lazily, so thread counts don't tell); a rebuild with the MSBuild property would settle it at the cost of a Keychain prompt: `DOTNET_gcConcurrent=0` (= `ConcurrentGarbageCollection=false`), `DOTNET_GCgen0size=0x100000`, `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1` (= `InvariantGlobalization`; would also force invariant date formats in "Paired devices ▸ last seen"). Server GC is already off for apps; `UseSystemResourceKeys` only shrinks the binary (clean, file-backed pages) and strips exception messages. The managed heap is ~3 MB ("Untagged" in `footprint`); the rest is AppKit/Security malloc.
- Pairing UI is already lazy (the NSPanel and CIContext are created on Show).
- Footprint grows ~3–5 MB over 5 min of 120 Hz input and stays there (not investigated further).

### How to measure memory (idle budget)
**Capture off first:** `scripts/latency-report.sh --disable`, then restart the app (the capture setting persists and costs memory/CPU while on). Record **idle CPU** (`ps -o %cpu`, expect 0.0) and **footprint** (`footprint <pid>`, what Activity Monitor's Memory column shows) as the budget metrics; RSS alongside for comparison only.
```bash
P=$(pgrep -x PenBridge)
ps -o rss=,%cpu= -p $P                       # RSS in KB (includes shared framework pages)
footprint -p $P | head -30                   # "Footprint: N MB" = Activity Monitor's Memory; per-category dirty
vmmap --summary $P | grep -E 'Physical footprint|Writable regions'
vmmap $P | awk '/^__TEXT/{print $NF}' | sort -u | wc -l   # loaded images
```
- Try runtime knobs without rebuilding (no new cdhash → no new Keychain prompt): `open -n --env DOTNET_gcConcurrent=0 <app>` (the `DOTNET_*` GC/globalization variables; see the caveat above).
- Wait until the log shows "Server listening" (a fresh Release build blocks on the Keychain prompt first; ADR-0017: one prompt per new build), then 30 s, then measure. Launch time: `open -n` timestamp → the "PenBridge … launched" os_log line (logged right after the status item is created).
- Connected-idle and streaming need a client that stays connected: SimClient `draw` disconnects after its script, and a SIGSTOPped client times out (the server drops a control channel silent for a few seconds). A throwaway file-based app (`#:project src/PenBridge.Core/...csproj`) using `PenBridgeClient.ConnectAsync` with SimClient's store (`~/.penbridge/simclient`, saved host/port/fingerprint under `simclient.last-server`) can hold or stream. Stream hover (InRange, no Contact) for long runs, so minutes of left-drags don't land on the user's desktop.
- SimClient's saved port may be stale (`simclient.last-server`): pass `--port 47820` when `draw` says ConnectionFailed and the server log shows no connection.
