# Toolchain

Source of truth: `scripts/bootstrap.sh`, `scripts/doctor.sh`, `scripts/lib/common.sh`, `docs/development.md` (Troubleshooting). Fix this skill when they change.

```bash
scripts/doctor.sh                       # read-only ✓/✗ + fix hints; exit 1 if something required is missing
scripts/bootstrap.sh [--skip-android] [--skip-workloads]   # idempotent; never runs sudo, prints sudo commands
```
bootstrap: Homebrew `openjdk@17` + `android-commandlinetools` cask (seed), Android SDK in `~/Library/Android/sdk` (platform-tools, emulator, `platforms;android-36`, `build-tools;36.0.0`, arm64 Google APIs image, licenses), `git config core.hooksPath .githooks`; prints env vars, writes no profile.

## Steps only the user can do (agents: ask, don't attempt)
- **Workloads** — `/usr/local/share/dotnet` is root-owned, so install needs sudo:
  `cd <repo> && sudo dotnet workload install macos android ios` (from the repo so `global.json` picks the SDK band); later `sudo dotnet workload update`. Never `chown` the dotnet root.
- **Xcode** — the current macos workload pack (macOS 27.0 SDK) expects **Xcode 27**. After installing from the App Store and launching once:
  ```bash
  sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
  sudo xcodebuild -license accept
  sudo xcodebuild -runFirstLaunch
  ```
  `-runFirstLaunch` installs `XcodeSystemResources.pkg` (CoreSimulator framework, device types, CoreDevice DDIs), `MobileDevice*.pkg` (usbmuxd, device frameworks) and `CoreTypes.pkg`. `dotnet build` of the Mac and iOS heads needs none of them: they call only clang/ld/`install_name_tool`/codesign/`mdimport` (+ `mono-aot-cross` for iOS), and the iOS head builds with zero simulator runtimes installed. Running on a simulator/device does need them (plus a runtime: `xcodebuild -downloadPlatform iOS`), so doctor only warns (!) when `xcodebuild -checkFirstLaunchStatus` fails (#25). Revisit if the iOS head gains asset catalogs/storyboards (actool/ibtool use a simulator runtime).
  Version-mismatch error → install the Xcode it names; temporary escape hatch for a minor mismatch: `-p:ValidateXcodeVersion=false`.
- **`scripts/mac-dev-cert.sh`** — prompts for the login password (skill `mac-build-run`). Once it exists, every Mac build (`dotnet build`/`run`, Rider, scripts) signs with "PenBridge Dev" automatically (csproj target, #55); without it builds sign ad-hoc and print a hint.
- **Wireless adb pairing** — needs the code shown on the phone (skill `android-build-run`).

## Gotchas
- **JDK**: .NET 10 Android workload accepts JDK 17.0–21.x; we use Homebrew `openjdk@17` (keg-only, not in `/usr/libexec/java_home`). Scripts find it under `$(brew --prefix)/opt/openjdk@17`. The JDK home is **`$(brew --prefix)/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home`** — the keg root (`…/opt/openjdk@17`) has a working `bin/java` but MSBuild rejects it (`XA5300 … Could not find required file 'jvm'`). `jdk_ok` requires a `release` file and `lib/server/libjvm.dylib`, so doctor rejects a keg-root `JAVA_HOME` and prints the correct `…/Contents/Home` path. A `JAVA_HOME` > 21 breaks Android builds (doctor warns).
- **sdkmanager** (cmdline-tools 23+) hands off to the new `android` CLI ("deprecated, Android CLI will be used instead") with a different `--list_installed` format (`platforms/android-36` paths). Scripts detect installed packages via `<sdk>/<path>/package.xml` — don't parse sdkmanager output. First run self-downloads and shows a metrics notice (`--no-metrics`).
- **Raw `dotnet build` / Rider** for Android need no env vars (issue #33). `Directory.Build.targets`, for `TargetPlatformIdentifier == android` on macOS only, sets `JavaSdkDirectory` to Homebrew `openjdk@17`'s `…/Contents/Home` (`/opt/homebrew`, then `/usr/local`) when `JavaSdkDirectory` and `JAVA_HOME` are unset, and `AndroidSdkDirectory` to `$(HOME)/Library/Android/sdk` when it, `ANDROID_HOME` and `ANDROID_SDK_ROOT` are unset. Each default applies only if the directory exists. Explicit `-p:`, Rider's Android SDK/JDK settings and env vars win; CI never hits it. Check with `dotnet msbuild src/PenBridge.Android -getProperty:JavaSdkDirectory` (empty = the env var is used) or doctor's "Android build resolution" section. Keep `resolve_java_home`/`resolve_android_home` in `scripts/lib/common.sh` in the same order. Without a JDK, the workload also warns `'/usr/libexec/java_home -X' … Root element is missing`. That's harmless: `TreatWarningsAsErrors` doesn't promote MSBuild task warnings.
- **`env -i` builds** (the way to prove a build is env-free; it relies on the auto-detection above): keep `HOME`, `PATH` and `TMPDIR`, or NuGet uses `/tmp/NuGetScratch`, which is root-owned after a `sudo dotnet workload install`, and fails with "Unable to obtain lock file access".
- **BouncyCastle trimming (IL2104, #27) and the dropped assembly (#46):** `BouncyCastle.Cryptography` ships without `IsTrimmable` metadata, so partial trim (Android Release, iOS) copies it whole yet still analyses all of it (unused OpenPGP code → IL2045 → IL2104, an error under warnings-as-errors). Rooting it doesn't help (still analysed). `Directory.Build.targets` (`PenBridgeTrimBouncyCastle`, after `PrepareForILLink`) sets `IsTrimmable=true`/`TrimMode=link` on its `ManagedAssemblyToLink` item, so ILLink keeps and analyses only the code Core reaches. Never suppress the warning.
  - **Only when the build really trims.** The Mac head defaults to `LinkMode=None` (Debug and Release): ILLink still runs, every assembly gets `TrimMode=copy`, and the macOS SDK passes `--custom-data DisableMarkingOfCopyAssemblies=true`, so ILLink never walks the code inside copied assemblies (Core, BCL). Nothing then marks Core's BouncyCastle references, a `link` BouncyCastle has no marked code, and ILLink **drops the whole dll**: the app starts, then pairing fails with `FileNotFoundException`/"server closed the connection" (#46). So the target is skipped when `TrimMode == copy` or `_ExtraTrimmerArgs` has `DisableMarkingOfCopyAssemblies`. General rule: never give an assembly a stricter per-assembly trim mode than the code referencing it gets marked with. When P2-E switches the Mac to full trim/NativeAOT the target applies there too (fine: Core is then linked and marks what it uses).
  - Not reflection: J-PAKE, `Sha256Digest`, `SecureRandom` are reached statically; trimmed partial/full and NativeAOT SimClient pair fine. No descriptor XML or rooting needed.
  - **Guards (CI):** `scripts/check-bundle.sh --mac|--android|--ios <config>` (reference closure of the bundle + J-PAKE types present whenever `PairingSession` is; a .NET file-based app `scripts/lib/check-bundle.cs`, run via `dotnet run --file`) and `scripts/smoke-trimmed-pairing.sh` (SimClient trimmed partial+full, optional `--aot`, real pairing + `draw line` in-process; a proxy, not the heads' bundling). Android: the APK uses a compressed assembly store, so check `obj/<config>/net10.0-android/<rid>/linked`; Release `linked/` lacks Core entirely while the head doesn't call it, which is correct.
  - Incremental builds don't delete a dll that a later build drops, so clean `bin`/`obj` of the head before trusting a bundle check after changing trim settings. Verify with Release builds of all three heads; any new non-trimmable package gets the same treatment.
- **CA1711** (`AnalysisLevel latest-recommended` + warnings-as-errors) rejects Apple's `AppDelegate`/`SceneDelegate` names; the Mac/iOS csproj files carry `NoWarn CA1711`.
- **CI: Xcode and workload are coupled.** `dotnet workload install macos|ios` takes the newest workload set for the SDK band, and its packs (e.g. `Microsoft.macOS.Sdk.net10.0_27.0`) refuse any Xcode but the matching major.minor. The workload version moves without us changing anything, so `macos-latest` + `setup-xcode latest-stable` broke (image had only Xcode 26.x). CI therefore pins the runner label `xcode-27` (hosted Xcode 27 image, check the actions/runner-images README for labels) and `.github/actions/select-xcode` (default `27.0`, fails fast listing installed Xcodes; sets `DEVELOPER_DIR`). Mac/iOS jobs print `xcodebuild -version` + `dotnet workload list`. When the workload moves to a new Xcode (error names it), bump the action default and, if needed, the runner label; `xcode-27` is a preview label, so revisit when an Xcode 27 GA image (e.g. `macos-27`) lands. `.github/actionlint.yaml` whitelists the label for actionlint.
- **Core tests** need no workloads: `scripts/test.sh` (= `dotnet test --project tests/PenBridge.Core.Tests`; MTP via `global.json`, the `dotnet test <path>` form is rejected; filters like `--filter-class "*Protocol*"`).
